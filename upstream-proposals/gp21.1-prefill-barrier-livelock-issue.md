# Draft GitHub issue (not submitted)

## Title

Scheduler can livelock active prefill when an allocator-rejected FIFO waiter is followed by another waiter

## Description

With chunked prefill and `prefill_batch_barrier` enabled, a request already in the active prefill cohort can stop making progress after a new waiter is rejected by KV allocation. A reduced CPU scheduler reproducer was confirmed against Definitive source tags `v0.2.2`, `v0.2.2-post2`, and `v0.2.2-post3`; no GPU is needed to reproduce the scheduling state.

The relevant path is `Scheduler.schedule()` in `vllm/v1/core/sched/scheduler.py`:

1. A running long prompt has already made a partial chunk.
2. Two more long prompts arrive, in FIFO order.
3. The allocator rejects the FIFO head under `full_sequence_must_fit`, and that request is recorded in `_prefill_barrier_admission_blocked`.
4. The frontier builder skips that blocked request but can still add the later waiter, even though admission will not reach it before the rejected head.
5. The active prefill chunk is aligned against this unreachable waiter. The scheduler returns an empty token batch, so the running request cannot reach the point where the rejected head can be retried.

Expected behavior: preserve FIFO admission and the barrier, keep unreachable later waiters out of the current alignment frontier, and allow the active prefill cohort to progress. Retry the rejected head when that cohort drains. Keep `full_sequence_must_fit` enabled.

## Minimal reproducer

The test `test_prefill_barrier_does_not_promote_waiters_past_blocked_fifo_head` in the attached patch uses `max_num_seqs=2`, `max_num_batched_tokens=512`, `max_model_len=1024`, `block_size=16`, three 1024-token prompts, and `prefill_batch_barrier=True`. It asserts the allocator rejection, checks that the active request continues to schedule tokens, and runs all requests to completion without an empty scheduler batch.

## Proposed fix

The patch prevents any waiting request from entering the prefill frontier while an allocator-rejected FIFO waiter is marked, then stops the waiting-admission loop while the active prefill barrier cohort remains. The marker is retried after the active cohort drains. No allocator, cache, DFlash, or GPU behavior is changed.

## Validation

- The regression was reproduced on Definitive `v0.2.2`, `v0.2.2-post2`, and `v0.2.2-post3` source lines using the reduced CPU scheduler test.
- The patched local candidate passed the focused CPU regression subset: `9 passed, 305 deselected, 15 warnings in 25.44s`, including this reproducer.
- The proposed two-file patch applies cleanly to `v0.2.2`, `v0.2.2-post2`, `v0.2.2-post3`, and the locally available upstream `main` ref. The test was not separately executed in four independent clean checkouts.
- This report concerns the FIFO/frontier livelock and is separate from the earlier upstream Mamba-alignment livelock fix.
